Three ways to build agents in Microsoft 365

Choose the simplest tool that does the job, and step up when you need actions, workflows and governance.

USE

Microsoft 365 Copilot + agents

Copilot works across Word, Excel, PowerPoint, Outlook and Teams, grounded in the user's own permissions. Prebuilt agents such as Researcher and Analyst handle deeper work.

  • Chat grounded in work data and the web, as your policy allows
  • Agents appear in the Copilot app and Teams
  • Enterprise data protection
For: every participant, every day
DESCRIBE

Agent Builder (in Microsoft 365 Copilot)

Build a declarative agent with no code. Describe what you want in plain language, add SharePoint knowledge and starter prompts, then share it with your team.

  • Natural-language Describe tab, or Configure
  • Knowledge: SharePoint sites, folders and files
  • Fastest path from idea to a working agent
For: Q&A and briefing agents (Navigator, Siting Explainer)
BUILD & GOVERN

Copilot Studio

A low-code studio for agents that take action. It adds topics, generative orchestration, tools and Power Automate flows, and publishes to Teams and Microsoft 365 Copilot.

  • Agent actions and Power Automate flows
  • Environments, DLP, analytics and ALM
  • Structured output (JSON) for workflows
For: triage, routing and approval workflows (all headline agents)

Ready for GCC

What's available. Microsoft 365 Copilot has been generally available in GCC since December 2024. Agent Builder is available in GCC. Copilot Studio offers US Government (GCC) plans and environments.
Check before class. In GCC, Agent Builder doesn't support embedded file content as a knowledge source, so use SharePoint sites and folders. Put SharePoint, Approvals, Teams, Outlook, Planner and the Copilot Studio connectors in the same DLP "Business" group, and use a dedicated environment.
